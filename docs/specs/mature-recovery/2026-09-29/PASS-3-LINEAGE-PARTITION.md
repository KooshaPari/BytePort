## Consequences for ontology and implementation mapping

Do not derive mature requirements from every current Rust crate. First ask whether the crate:
1. realizes BP-L1 accepted behavior;
2. is a reusable shared primitive consumed by BP-L1;
3. is compatibility debt;
4. belongs in another repository;
5. or is superseded/experimental residue.

In particular, “transport,” “codec,” “port,” generic S3 upload, terminal UI adapters and vendor AWS runtime code need consumer/caller mapping before entering the mature contract.

This also explains why current-repo breadth can be misleading: BytePort may contain substantial code that is not evidence of product completion.
